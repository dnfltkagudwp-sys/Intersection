# 교차점 — 초반 데이터 제작 패킷 v0.3

> 기준: `Docs/GameDesign.md`의 **증거 마스터표**와 본문. v0.1·v0.2 패킷은 사용하지 않아. 이 패킷은 **더미 제작 규칙 → P0~P2 및 첫 B 의심에 쓰는 실제 기록 → 클로드 구현 지시** 순서야. 시제품용 이름·정확한 분 단위 시각·일상 문구는 교체 가능해. 사건의 미확정 설정은 확정하지 않아.

## v0.3 수정 고정사항

- B와 D의 접점 `D-134~131` 뒤인 `D-128`에 D 관련 익명 계정 정황이 나타나도록 순서를 고정해. B가 D를 알기 전 피해 정황이 먼저 생기지 않아.
- B가 A를 봤다고 말하는 날짜와 장소를 A01 촬영 기록에 맞춰. `B02-M1`은 `D-21` 후문, `B02-M2`는 `D-12` 버스정류장이야.
- A06 묶음 안의 D 전용 자료 5개는 고유 ID `D01-01~05`를 쓰고 `parentId: A06`으로 연결해. `A06-07~11`은 사용하지 않아.
- B01은 SNS 프로필이 아니라 `D-5` 로컬 갤러리의 일상 사진이며 내부 자산 ID는 `face-b-daily`야.
- `A06-05`의 여성은 작가용 미상 인물 E로 고정해. D가 아니며 화면에는 E라는 호칭도 노출하지 않아.
- `B02-M4`는 사건 전날의 미이행 약속이 아니라 `D-3`의 평범한 하교 동행 요청이야. 사건 당일 B가 혼자 폐상가로 가는 흐름과 충돌하지 않아.

## 0. 제작 경계

- 이번 구간의 끝은 `B04/B05`에서 C와 B의 친분을 알고, A의 `D01`과 B 로컬의 `B06`을 교차해 **“C도 B와 연결되고 D도 B와 연결된다”**는 첫 의심에 닿는 지점이야.
- `B07`은 P1부터 실제로 있지만, C의 평범한 사진처럼 보여. A06 게시물과의 파일 계보 판정 `CROSS-1`은 **P3에서 B08이 들어온 뒤** 다뤄. P2에 `A06+B07` 자동 일치 메시지를 띄우지 않아.
- A가 폐상가 위치를 보내 B를 부르고, A가 먼저 도착해. 현장 내부 대화·몸싸움의 시작점은 끝까지 확정하지 않아.
- A가 B를 처음 후보로 좁힌 계기, 사건 당일 “찾았다”의 마지막 캡처 내용, A13의 수신인, D의 구체적 피해 수위는 미정이야. 내용을 지어 넣지 않아.
- A/B 로컬은 기기 등록 시 존재하고, 클라우드는 각 의뢰의 표준 연동 완료 후 접근 가능해. P2 이후 자료의 **의미를 깨닫는 시점**과 **존재 시점**을 구분해.

## 1. 더미·생활 데이터 제작 규칙

### 1-1. 역할과 양

더미 데이터는 랜덤 노이즈가 아니라 A와 B가 평소에 남긴 **고정된 생활 기록**이야. 사건과 무관해도 업무상 분류·검색·핀 대상이 될 수 있어.

| 구간 | 제작 목표 | 목록에서의 역할 |
| --- | --- | --- |
| A 로컬 | A01 사진 18장(6일) + A02 검색 5~6·캡처 4~5·지도 2~3 + A03 대화 1방 + C 대화 1방 + 일반 항목 12개 안팎 | 일상 갤러리·브라우저·대화 사이에 도촬→신상털기→압박이 누적돼. |
| B 로컬 | B02 수주간의 친구 대화·검색·설정, B04/C 사진 5~7장, B06/D 접점, 일반 항목 14개 안팎 | 최근엔 스토킹에 대한 실제 공포가 보이고, 옛 C/D 기록은 지인 자료로 매몰돼. |
| A 첫 클라우드 | A06 캡처 15~20장, A07 대조표, D01 자료, 일반 백업 5개 안팎 | 여러 여성·계정이 나와 A가 더 위험해 보일 여지가 있어. A08을 읽은 뒤에야 조사 목적이 조금 보이기 시작해. |

한 대화방은 목록에서 한 행이지만 안쪽 메시지는 각각 열람·핀·검색될 수 있어. 대량 파일 수를 꾸며내지 않아. 최종 삭제 수치를 쓰려면 실제 묶음 항목의 수량과 합계를 별도로 정의해.

### 1-2. 데이터 구조와 접근

각 기록에 `id`, `owner(A/B/업무)`, `source(로컬/클라우드/연동)`, `type`, `parentId`, `time`, `title`, `preview`, `body`, 선택적 `mediaAssetId`, `availability`, `reviewState`를 둬. `reviewState`는 미분류·보존 후보·삭제 후보야. 열람·핀·비교 상태와 분리해 저장해.

- **검색:** 지금 접근·인덱싱된 자료의 화면상 문구, 파일명, 대화 상대, 날짜만 필터링해. 내부 ID·작가용 설명·미래 결론은 인덱싱하지 않아. 검색이 새 데이터를 만들거나 기존 로컬 기록을 해금하지 않아.
- **사진:** 같은 얼굴·동일 자료의 자산 ID는 내부에서만 연결해. B01과 A01 일치 팝업이나 자동 정답 자막은 없어. 실제 이미지가 없으면 얼굴 인식 플레이 테스트는 미완료야.
- **비교:** 모든 항목을 핀·나란히 보기 할 수 있어. 무관한 일반 자료에도 ‘틀린 증거’ 표시가 없어. `D01+B06`의 관계는 플레이어가 알아차리게 하고, `CROSS-1` 판정은 P3 전에는 만들지 않아.
- **업무:** 보존·삭제 후보는 실제 삭제가 아니야. 마지막 작업 전까지 언제든 재열람·재분류할 수 있어.

### 1-3. 생활 기록 작성과 검수

1. A는 가족·수업·아르바이트·일상 사진이 있고, B도 가족·친구·학교·취미가 있어. B의 모든 일상을 나중에 위장 암호로 바꾸지 않아.
2. 일상 더미에 C/D 사진의 식별 지점, 익명 계정명, 같은 시각·장소를 우연히 재사용하지 않아. 의도치 않은 거짓 연결을 막아.
3. 사건을 해설하는 일기·`B 조사자료.docx` 같은 파일을 추가하지 않아. 검색→SNS 캡처→지도→일반 사진의 실제 사용 흔적을 흩어 둬.
4. B의 두려움은 진짜야. SNS 비공개, 문자 알림 끄기, 귀가경로 변경을 기능·설정 로그와 대화 속에 분산해. 후반에 전부 연기로 뒤집지 않아.
5. C/D의 사적·가공 이미지는 직접적인 노출 없이 가림·썸네일·일반 사진의 비민감한 특징으로만 보여줘.
6. A의 미행·도촬·압박은 목적이 재해석돼도 잘못된 행동으로 남아. C의 삭제 의사도 끝까지 유지해.
7. P0/P1을 깊게 탐색하면 A가 C와 오래된 온라인 문제를 겪었고 B가 C/D와 아는 사이라는 정보까지는 알 수 있어. B의 계정 운영을 단독 확정할 로그는 없어.

### 첫 의심의 도달점

A06/A07에서 “A가 B 외 다른 여성들까지 조사했다”는 인상을 받고, A08로 C의 온라인 피해와 A의 초기 도움을 알아. 이미 있던 B04/B05는 C와 B의 친분·자료 접근 가능성으로 재해석돼. 그다음 `D01`의 D 얼굴·이름을 B의 `B06` 대화·단체사진에서 찾아 **두 번째 우연**을 알아차려. 시스템은 “B가 가해자”라고 말하지 않아. C 사진의 원본/중간 편집본/게시물 계보는 P3에서 이어져.

## 7. 구현 전 확인 항목

- A03/B03 대화는 최신 원문 7구간이 **한 데이터 원본**으로 양쪽에서 똑같이 보여야 해. 초반 위협과 B의 거부가 거짓으로 바뀌면 안 돼.
- A가 위치를 보내고 A가 먼저 도착해. B가 초대한 로그, SH02, 현장 녹취·CCTV는 없어.
- A01 18장/6일은 일반 갤러리에 있고, B02-M1 `D-21` 후문과 B02-M2 `D-12` 버스정류장은 같은 날 A01 촬영 기록과 맞아. B02-M4는 `D-3` 하교 동행 요청이라 사건 당일 혼자 폐상가로 가는 흐름과 충돌하지 않아.
- B06은 B↔D야. `D-134` 사진과 `D-132~131` 대화가 `D-128` D 관련 계정 정황보다 앞서. A09는 보류되어 어떤 본문에도 들어가지 않아.
- B05-01의 사진 전송은 `D-225 16:40`으로 카페 약속 직전이고, `D-224`의 “어제”와 맞아.
- A06은 `Screenshots/Download`의 18개 일반 캡처 묶음이며, 그 안의 D 자료 5개는 `D01-01~05`와 `parentId: A06`을 사용해. `A06-07~11`은 만들지 않아. `CROSS-1`은 P3 이후야.

- B의 범행은 C/D 접점 두 개만으로 확정되지 않아. P3/P4의 파일 계보·계정 소유·반복 편집 축이 필요해.
