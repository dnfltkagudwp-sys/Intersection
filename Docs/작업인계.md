## 2. 남은 확인·판단 사항

P2 1차 연결에서 사용자 판단이 필요한 것:
- 메인 카메라의 후처리(URP 샘플 Global Volume: Tonemapping·Bloom·Vignette)가 UI에도 적용되어 흰색이 약 84% 밝기로 보인다(캡처 PNG 자체는 정상). 끄려면 `Main.unity`(카메라 후처리) 또는 볼륨 프로필을 바꿔야 한다.
- 1366×768에서 캡처 안 글자가 약 9~10px로 작다(전사본 줄과 화면 줄을 맞추려면 댓글·안내 본문을 더 키울 수 없음). 크게 보기 화면 등은 별도 결정.
- 휴대전화 상세 상단 제목이 긴 파일명에서 `c…`처럼 잘린다(기존 레이아웃, 1366에서 두드러짐).


수동 확인 완료 (2026-10-12 사용자): 실제 키보드(Esc·Tab·Shift+Tab·P·1·2·0), 1366×768에서 고정 자료 3개 + 비교 1/2·2/2 마우스 휠, 우측 패널 잘림 없음.

정식 콘텐츠 작업 중에 함께 볼 것 (정식 데이터가 있어야 의미 있음):
- 파일 미리보기 문서(표시 문구)의 실제 가독성: 긴 표·로그 줄이 휴대전화 폭에서 줄바꿈될 때, 1366×768에서
- 실제로 플레이 도중 에디터를 강제 종료했을 때의 진행 저장 (자동 검수는 예외 주입으로만 했다)
- 작업함 행의 보존/삭제·메모 표시가 정식 자료 제목 옆에서 눈에 잘 띄는지

보고했지만 사용자 결정이 아직 없는 것:
- 사용자가 본 `요청 4/2`라는 표시는 문자열에 없었다. 튜토리얼 `2/4`와 비교 `0/2`가 붙어 보였던 것으로 추정되며 둘 다 제거했다. 다시 보이면 위치 확인.
- 보존 지정 직후 하단 줄은 그냥 숨긴다(지정됨 표시는 요청 패널에만).
- 비교 칸이 찼을 때 늘 보이던 "먼저 빼 주세요" 안내를 없앴다. 추가를 시도할 때만 안내.
- 구버전 세이브에서 튜토리얼을 다 깼어도 P0이고 가족사진이 지금 보존이 아니면 다시 보존해야 A 인벤토리를 시작할 수 있다(P1 이상 세이브는 영향 없음).

## 3. 커밋하지 않고 둔 로컬 변경

원래 컴퓨터에 아래 변경이 커밋되지 않은 채 남아 있다. 다른 컴퓨터에는 없으며 작업에 영향은 없다.
- 폰트 SDF 4개: 플레이 중 동적 아틀라스 갱신
- 프리팹 15개, `Theme.asset`, URP 설정, ProjectSettings 5개: 줄바꿈(LF/CRLF)만 다름

## 4. 테스트할 때 지킬 것 (사용자 지시)

- **테스트 전후로 세이브를 모두 지운다.** `Application.persistentDataPath`(Windows: `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Intersection`)의 `work_state.json`, `progress_state.json` 두 개.
  - 메뉴 `Intersection/Progress/Delete Progress Save (New Game)`는 `progress_state.json`만 지우고 플레이 중에는 동작하지 않는다. `work_state.json`은 따로 지워야 한다.
  - 내가 만들지 않은 세이브가 있으면 사용자가 에디터에서 테스트한 것이니 백업 없이 그냥 지워도 된다(2026-10-12 사용자 확인).
- **스크린샷은 폴더에 쌓지 않는다.** 대화에 중요한 몇 장만 보여주고 나머지는 지운다.
- 사용자가 "그것만", "이것만"이라고 하면 그 범위만 하고 다음 제안·추가 작업 없이 멈춘다. 커밋 정리만 요청하면 커밋만 한다.

## 5. Unity MCP로 플레이 테스트하는 방법

이 프로젝트에 연결된 `unity-mcp`(com.unity.ai.assistant)는 C# 실행(`Unity_RunCommand`), 콘솔 로그, 카메라/씬 캡처, 에셋 생성 도구만 제공한다. 플레이 조작은 모두 C# 실행으로 한다.

- **플레이 시작·종료:** `EditorApplication.isPlaying = true/false`. 프로젝트가 도메인 리로드를 끄고 있어 플레이 중에도 MCP 연결이 유지된다.
- **클릭:** `Button`을 자식 `TMP_Text` 라벨로 찾아 `ExecuteEvents.Execute(go, new PointerEventData(EventSystem.current), ExecuteEvents.pointerClickHandler)`.
  - 같은 라벨이 여러 곳에 있다(예: 작업 기록 행 안의 `유족 요청`·`보존`). 텍스트가 하나뿐인 버튼을 우선하고, 좌측 사이드바 항목은 x 좌표가 가장 작은 것을 고른다.
  - 다시 그려지는 행(작업 기록 등)은 매번 새로 찾는다. 이전에 찾은 참조는 무효가 된다.
- **스크린샷:** 에디터 창에 포커스가 없으면 `ScreenCapture.CaptureScreenshot`이 늦거나 저장되지 않는다. 캔버스가 Screen Space - Camera이므로 `Canvas.worldCamera`를 RenderTexture에 `Render()` → `ReadPixels` → PNG로 바로 쓴다.
- **막히는 것:** RunCommand 안에서는 `System.Reflection`(private 필드 접근)과 파일 이동·삭제가 차단된다("User interactions are not supported"). 세이브 삭제 같은 파일 작업은 셸에서 한다.
- **스크립트 수정 직후:** Unity가 다시 컴파일하는 동안 MCP가 "Unity not detected"를 낸다. 20~40초 기다렸다 다시 시도한다.
- **콘솔:** 플레이에 들어가면 콘솔이 지워진다. 검증 결과 로그는 플레이 밖에서 확인한다. `Unity AI ... NoSubscription` 로그는 무시해도 된다.
- **실제 키 입력은 검증할 수 없다**(`Keyboard.current` 경로). 키보드 항목은 사용자에게 직접 확인을 부탁한다. Esc 단계 논리는 `shell.SendMessage("HandleEscape")`로 확인할 수 있다(실제 키 확인은 아님).
- **해상도별 캡처:** `PlayModeWindow.SetCustomRenderingResolution(1366, 768, "이름")` → 다음 명령에서 `Screen.width`가 바뀐 것을 확인 → 에디터가 백그라운드라 프레임이 돌지 않으므로 `CanvasScaler`를 껐다 켜서 배율을 다시 계산한 뒤 캡처한다. 이 API는 Game 뷰 크기 목록에 사용자 지정 항목을 추가하고 되돌리는 공개 API가 없으니, 끝나면 사용자에게 Game 뷰를 원래 크기(예: Free Aspect)로 돌려 달라고 알린다.
- **플레이 중에는 스크립트를 고치지 않는다.** 고칠 일이 생기면 먼저 플레이를 끄고 고친 뒤 Refresh로 컴파일한다(세이브는 디스크에 남아 이어서 검수 가능).

## 6. 작업 환경 메모

- 이 컴퓨터에서는 `git`이 PATH에 없어 GitHub Desktop에 포함된 git을 썼다: `%LOCALAPPDATA%\GitHubDesktop\app-*\resources\app\git\cmd\git.exe`. 사무실 컴퓨터에서는 다를 수 있다.
- `.mcp.json`(로컬 MCP 설정)은 컴퓨터마다 경로가 달라 git에서 제외했다. 새 컴퓨터에서는 Unity MCP를 다시 연결해야 한다.
- UI를 고치면 `Scripts/Editor/MainUIBuilder.cs`를 고친 뒤 메뉴 `Intersection/UI/Build Main Scene UI`로 다시 생성하고, `Intersection/Content/Validate`로 검증한다.
- 커밋 메시지 형식: `[AI/Feat] …`, `[AI/Fix] …`, `[Chore] …` (한국어 요약).
