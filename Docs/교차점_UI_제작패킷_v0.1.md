# 교차점 — UI 제작 패킷 v0.1

> 기준 문서: `Docs/GameDesign.md`, `Docs/교차점_초반데이터_제작패킷_v0.3.md`  
> 목적: 교차점의 **PC 업무 프로그램 외곽**과 **실제 휴대전화처럼 느껴지는 중앙 콘텐츠**를 구현하기 위한 별도 제작 기준이다.  
> 적용 범위: UI 구조·표현·조작·상태 관리. 사건 설정과 증거 내용은 위 두 기준 문서가 우선한다.

## v0.1 보완 고정사항

- 시안에 들어간 대화방 수, 앱별 개수, 실제 날짜, 미리보기 문구는 레이아웃 확인용이며 런타임 값으로 하드코딩하지 않는다.
- 대화방 목록·마지막 메시지 미리보기·정렬·개수는 현재 로드된 데이터에서 계산한다. 이후 더미 대화방과 메시지를 데이터에 추가해도 UI 코드를 고치지 않아야 한다.
- A/B/C/D는 내부 기획·데이터 식별용 역할 키다. 실제 화면에는 데이터에 저장된 인물 이름·연락처 저장명·단체방 제목을 사용하고, 아직 확인되지 않은 관계나 정체를 역할 키로 미리 노출하지 않는다.
- 메시지 구간과 개별 메시지의 참조 ID를 분리한다. 원본 ID는 배열 위치·표시 순서·날짜·이름에서 만들지 않는 불변 키로 두고, 순서는 별도 필드로 관리한다. A03/B03은 한 원본 대화를 공유하며 화면용 사본을 두 벌 만들지 않는다.
- 시안의 임시 선택 사각형과 말풍선은 구현 기준에서 제외한다. 선택 결과는 우측 작업 패널에 기록한다.
- UI-01에서 아직 구현하지 않는 선택·비교 기능은 작동하는 버튼처럼 두지 않는다. 숨기거나 명확한 비활성 상태로 처리한다.

## 0. 이 패킷의 사용법

이 문서를 구현 세션에 전달할 때는 사용자가 확정한 **UI 시안 이미지도 함께 첨부**한다.

첨부 이미지는 다음 요소의 참고 자료다.

- 전체적인 어두운 업무 프로그램 분위기
- 좌측 의뢰·앱 전환 / 중앙 휴대전화 원본 / 우측 업무 기록의 3단 구조
- 휴대전화 기기 안에서 실제 문자 앱을 열어보는 감각
- 바깥 업무 프로그램과 안쪽 개인 기록의 시각적 분리

첨부 이미지 자체가 픽셀 단위 명세는 아니다. 특히 이미지의 **증거 선택 사각형과 `A03-03으로 선택` 말풍선 위치는 임시 시안**이며 그대로 복제하지 않는다. 증거 선택 동작은 이 문서의 `7. 증거 선택·핀·비교` 규칙을 따른다.

이미지에 보이는 `메시지 8`, 대화방 3개, `9월 22일`, `9월 26일`, `A03 · B와의 메시지`, `< 7`도 확정 데이터나 확정 문구가 아니다. 실제 구현은 로드된 기록, `caseDate`, 현재 진행 단계에서 플레이어가 알고 있는 정보로 화면을 만든다.

충돌 시 우선순위는 다음과 같다.

1. `Docs/GameDesign.md`의 최신 사건·증거 마스터 기준
2. `Docs/교차점_초반데이터_제작패킷_v0.3.md`의 실제 데이터와 문구
3. 이 UI 제작 패킷의 조작·표현 규칙
4. 첨부 UI 시안 이미지의 분위기와 배치

이미지 때문에 새 단서, 새 메시지, 새 증거 ID를 만들지 않는다.

## 1. 한 문장 원칙

**바깥은 디지털 유산 정리 업무 프로그램이고, 중앙에서 기록을 여는 순간에는 실제 사망자의 휴대전화를 뒤져보는 것처럼 보여야 한다.**

이 두 층을 섞지 않는다.

| 층 | 역할 | 보이는 정보 |
| --- | --- | --- |
| PC 업무 프로그램 | 의뢰 전환, 동기화 상태, 분류, 핀, 메모, 비교 | 의뢰인·기기 소유자 이름, 출처, 기록 ID, `사망 N일 전`, 보존·삭제 후보, 메타데이터 |
| 휴대전화 원본 화면 | 사망자가 실제로 보았을 개인 기록 | 연락처명, 실제 날짜·시각, 메시지 말풍선, 사진첩, 검색 기록, 앱 내 탐색 |

### 휴대전화 안에 절대 넣지 않는 정보

- `A01`, `A03-03`, `B06` 같은 작가·구현용 증거 ID
- `D-14`, `P0`, `P3` 같은 기획용 상대 시점과 진행 단계
- `필수 증거`, `수상함`, `가해자`, `피해자`, `연결됨` 같은 해설
- `보존 후보`, `삭제 후보`, `핀됨` 같은 업무 상태 배지
- 자동 얼굴 일치, 자동 관계 판정, 정답 표시
- 플레이어에게 다음 목적지를 알려주는 퀘스트 마커

내부의 `D-14` 표기와 P0~P6 단계명은 제작 데이터와 개발·검수 도구에서만 사용한다. 플레이어 화면은 필요할 때 `사망 14일 전`처럼 변환된 표현을 휴대전화 바깥의 우측 업무 패널이나 비교 화면에 표시한다.

## 2. 전체 화면 구조

### 2-1. 상단 업무 바

상단은 차갑고 건조한 사내 프로그램처럼 보이게 한다.

- 프로그램명 또는 임시 브랜드
- 현재 의뢰 및 기기 상태
- 로컬/클라우드 인덱싱 진행률
- 현재 접근 가능한 자료 검색
- 보안 세션 또는 접속 상태
- 업무 알림

사건명을 자극적으로 표시하거나 “살인”, “범인” 같은 단어를 대시보드에 쓰지 않는다.

### 2-2. 좌측 — 의뢰와 앱 전환

좌측은 다음 두 구역으로 나눈다.

1. 두 의뢰 전환
2. 현재 휴대전화의 앱 전환

초기 앱 목록:

- 메시지
- 사진
- 브라우저
- 지도/위치
- 파일
- 이후 필요하면 계정·설정 기록

이 목록은 기본 구성 예시다. 실제 앱 표시명·순서·아이콘·공개 조건은 앱 등록 데이터에서 읽고 화면 코드나 프리팹 자식 순서로 결정하지 않는다.

최종 화면의 의뢰 전환에는 확정된 사망자 이름을 사용한다. A/B는 내부 식별자 또는 제작 중 임시 표시에만 쓸 수 있으며 최종 플레이어용 이름을 대신하지 않는다.

좌측 앱 버튼은 PC 업무 프로그램의 빠른 접근 장치다. 버튼을 눌렀을 때 중앙에 데이터 표를 띄우는 것이 아니라 **해당 휴대전화 앱의 최상위 화면**을 연다.

예:

- 메시지 → 대화방 목록
- 사진 → 앨범 또는 최근 항목 그리드
- 브라우저 → 열려 있던 탭 또는 방문 기록
- 지도 → 최근 검색·저장 장소
- 파일 → 실제 폴더 목록

휴대전화 홈 화면 전체를 완전하게 시뮬레이션하는 것은 v0.1 필수가 아니다. 대신 앱 안에서는 반드시 목록 → 상세 → 뒤로가기 흐름이 작동해야 한다.

### 2-3. 중앙 — 휴대전화 원본 열람

중앙의 기본 상태는 실제 스마트폰 기기 또는 스마트폰 화면 비율의 뷰어다.

- 기기 프레임은 분위기를 강화하지만 콘텐츠 면적을 지나치게 줄이지 않는다.
- 앱 상태바, 헤더, 뒤로가기, 목록, 상세 화면을 실제 모바일 앱의 문법으로 구성한다.
- 중앙에는 한 번에 한 휴대전화의 한 앱만 표시한다.
- 플레이어가 마지막으로 보던 앱과 내부 위치를 A/B별로 기억한다.
- A에서 B로 갔다가 돌아오면 A폰의 이전 대화방·사진 위치로 복귀한다.

시제품 기본 시각은 첨부 이미지처럼 **iOS 계열의 익숙한 문자 앱 문법**을 사용할 수 있다. 다만 상표 로고나 실제 앱 자산을 복제하지 말고, 프로젝트 자체 아이콘과 일반화된 모바일 UI로 만든다. A/B 모두 같은 UI 프레임을 재사용해도 되며, 데이터와 설정 상태만 달라진다.

### 2-4. 우측 — 업무 기록

우측 패널은 휴대전화 원본을 훼손하지 않고 플레이어의 업무 정보를 보여주는 곳이다.

기본 구성:

- 현재 열람 기록의 업무상 제목
- 확정된 기기 소유자 이름. 내부 A/B 식별자는 별도 데이터로 유지
- 출처: 로컬/클라우드/연동
- 내부 증거 ID
- 사망일 기준 기록 시각 또는 기록 기간
- 무결성·복구 상태
- 핀한 기록
- 작업메모
- 보존 후보/삭제 후보 지정
- 비교 진입

화면 제목은 작가용 인물 태그나 관계 분류로 조합하지 않는다. 예를 들어 P0의 A폰에서 상대가 B라는 사실을 아직 모르면 `A03 · B와의 메시지`가 아니라 `저장되지 않은 번호와의 대화`처럼 기기 안에서 확인 가능한 정보만 쓴다. 이름이 저장된 친구라면 실제 데이터의 이름 또는 저장명을 쓰고, 단순히 `친구`라고 표시하지 않는다. `A03` 같은 내부 ID가 필요하면 제목과 분리된 `기록 ID` 항목에 둔다.

한 대화방이 여러 시점에 걸쳐 있으면 `기획 시점`이라는 라벨이나 단일 `D-14` 값으로 대표하지 않는다.

- 대화방 전체: `기록 기간 · 사망 21일 전~사망 당일`
- 현재 선택한 메시지: `기록 시각 · 사망 14일 전 · 오후 9:23`

위 값 역시 원본 타임스탬프와 `caseDate`에서 계산한다.

우측 패널이 휴대전화보다 시각적으로 더 강해지지 않게 한다. 기본 상태에서는 좁고 건조한 보조 도구이며, 상세 메타데이터가 필요할 때만 확장한다.

## 3. 휴대전화를 뒤지는 감각

다음 원칙을 만족해야 한다.

1. 앱을 열면 곧바로 핵심 증거 하나만 크게 보여주지 않는다.
2. 평범한 기록 사이에서 플레이어가 직접 대화방·사진·방문 기록을 선택한다.
3. 목록의 정렬과 미리보기는 실제 사용 시각과 내용을 따른다.
4. 뒤로가기를 누르면 실제 앱처럼 이전 목록으로 돌아간다.
5. 앱 안 날짜는 자연스러운 달력 날짜와 시각으로 표시한다.
6. 읽지 않음, 알림 끄기, 비공개 전환 같은 상태는 실제 앱 설정이나 표시로 보인다.
7. 핵심 기록과 일상 더미가 같은 디자인·같은 상호작용을 사용한다.
8. 증거를 열었을 때 게임이 의미를 설명하지 않는다.

잘못된 예:

> `A03 / 필수 증거 / D-14 / 협박 메시지`

올바른 예:

> `저장되지 않은 번호` 대화방을 열면 `caseDate`에서 계산된 실제 날짜와 시각 아래 원래 말풍선들이 보인다. 우측 업무 패널에는 `기록 ID A03`, `사망 14일 전`처럼 플레이어용으로 분리·변환된 정보만 표시하고 `D-14` 자체는 노출하지 않는다.

### 실제 날짜 변환

내부 데이터는 `D-14`를 유지하되 휴대전화 표시 단계에서 `caseDate` 기준 실제 날짜로 변환한다.

- 내부: `D-14 21:18`
- 휴대전화: `formatPhoneDate(caseDate - 14일, 21:18)`의 결과
- 우측 업무 패널: `사망 14일 전 · 오후 9:18`

최종 사망일은 아직 확정하지 않았지만 실행 가능한 시제품에는 임시 `caseDate`가 필요하다. 임시 값은 기존 프로젝트 설정 방식에 맞춘 설정 파일·ScriptableObject 등 **한 곳에만** 둔다. 시안에 보인 날짜를 역산할 필요는 없으며, 나중에 `caseDate` 하나를 바꾸면 모든 실제 날짜와 `사망 N일 전` 표기가 함께 갱신되어야 한다. 날짜와 시각을 화면마다 직접 문자열로 중복 작성하지 않는다. 휴대전화 내부의 12시간/24시간 표기도 하나의 로케일 포매터를 사용해 통일한다.

### 3-1. 데이터 추가를 전제로 한 목록

현재 v0.3에 적힌 대화방은 최소 제작 데이터이지 영구적인 총개수가 아니다. 이후 일상 더미 대화방과 메시지를 계속 추가할 수 있어야 한다.

- 대화방 목록 행을 장면에 수동 배치하지 않는다.
- 앱 옆 개수는 현재 접근 가능한 대화방 데이터 수에서 계산한다.
- 목록 순서는 각 대화방의 마지막 메시지 시각으로 계산한다.
- 목록 미리보기는 실제 마지막 메시지 본문·첨부 유형에서 생성한다.
- 미리보기 생략은 UI의 한 줄 말줄임으로 처리한다. 별도의 잘린 문장을 데이터에 저장하지 않는다.
- 검색 결과, 읽지 않음 표시, 알림 끄기 표시는 실제 상태 데이터가 있을 때만 나타난다.
- 더미 대화방도 핵심 대화와 같은 데이터 구조와 같은 프리팹/컴포넌트를 사용한다.
- 데이터가 아직 덜 채워진 제작 단계에서는 잘못된 고정 숫자를 보여주기보다 개수 표시를 숨길 수 있다.

현재 v0.3 기준 A폰에서 확인되는 메시지 대화방은 A03, C와의 대화방, 가족 대화, 조별 과제, 아르바이트, 친구 대화가 있지만, 이는 기획상 역할 구분일 뿐 최종 연락처명 목록이 아니다. 실제 더미 데이터를 만들 때 가족·친구·담당자에게 이름 또는 자연스러운 저장명을 부여하고, 단체방에는 실제 방 제목을 둔다. 이를 최종 6개로 고정하지 않으며 이후 더미 데이터를 추가하면 자동으로 목록과 개수가 늘어나야 한다.

## 4. 메시지 앱 — 최우선 구현

UI 1차 구현은 메시지 앱을 기준으로 완성한다. 사진·브라우저보다 먼저 메시지 앱에서 “실제 폰을 본다”는 감각을 검증한다.

### 4-1. 대화방 목록

필수 요소:

- 모바일 상태바
- 메시지 앱 제목
- 앱 내부 검색창
- 연락처 또는 저장되지 않은 번호
- 마지막 메시지 미리보기
- 실제 날짜·시각
- 읽음/알림 상태가 필요할 때의 일반적인 표시
- 목록 행을 눌러 대화방 진입

상태바 시계는 선택한 메시지 시각이나 `caseDate`가 아니라 실행 중인 PC의 현재 현지 시각을 표시한다. 인터넷 시간 조회는 필요 없고, 한 곳의 시계 공급부에서 값을 받아 분이 바뀔 때와 앱 포커스 복귀 시 갱신한다. 테스트·스크린샷에서는 같은 공급부를 고정 시각으로 교체할 수 있어야 하며, 상태바 시계는 스토리·정렬·진행 로직에 사용하지 않는다.

메시지 목록의 `오늘`, `어제`, 요일 표시는 PC 현재 날짜가 아니라 휴대전화 기록의 기준일인 `caseDate`를 기준으로 계산한다. 상태바에는 현재 시각만 보이고 기록 날짜 표기는 사망 당시의 휴대전화 목록 상태를 재현한다. `caseDate`가 PC 날짜보다 과거나 미래여도 목록 날짜가 PC 시계 때문에 바뀌지 않아야 한다. 절대 날짜가 필요한 오래된 기록도 같은 포매터에서 계산한다.

A폰의 초기 목록에는 핵심 대화만 두지 않는다. v0.3 패킷에서 가족·조별 과제·아르바이트·친구·C 관계로 설명한 평범한 방이 함께 보여야 하며, 실제 화면에는 각 데이터에 지정된 사람 이름·저장명·단체방 제목을 쓴다.

B폰도 같은 방식으로 이름이 지정된 친구·가족, 실제 조별 과제 방 제목, A와의 `모르는 번호`, C/D의 실제 이름으로 된 오래된 대화가 자연스러운 정렬로 섞인다. `친구`, `가족`, `C`, `D` 자체를 연락처명으로 쓰지 않는다. 단, 사용자가 실제로 그렇게 저장했다는 별도 설정이 있는 경우는 예외다.

대화방의 화면 제목은 기기 소유자의 주소록과 당시 화면 상태에서 가져온다. 이름이 저장된 1:1 대화는 실제 이름 또는 저장명을 쓰고, 단체방은 방 제목을 쓴다. A폰에서 아직 저장되지 않은 상대를 작가용 호칭 `B`로 바꾸거나, B폰의 `모르는 번호`를 `A`로 바꾸지 않는다.

목록의 마지막 메시지와 날짜는 별도 고정 문자열이 아니다. 메시지가 추가되면 최신 메시지, 미리보기, 정렬 위치가 함께 바뀐다. 따라서 A03/A12 대화는 사건 당일까지 모두 들어간 상태라면 마지막 B 메시지 `알겠어`가 목록 미리보기가 된다.

뒤로가기의 숫자는 실제 읽지 않음 상태에서 계산할 때만 쓴다. 읽지 않음 데이터를 아직 만들지 않았다면 `< 7` 같은 임의 숫자 대신 `메시지` 또는 플랫폼에 맞는 중립적인 뒤로가기 라벨을 쓴다.

### 4-2. 대화방 상세

필수 요소:

- 실제 연락처 표기
- 뒤로가기
- 발신/수신 방향이 구분되는 말풍선
- 구간 날짜 구분
- 메시지 시각
- 첨부 이미지와 위치 공유의 앱 내 표현
- 입력창은 보이되 사망자의 폰에서 새 메시지를 실제 전송할 수는 없음

말풍선은 모바일 문자 앱처럼 자연스럽게 구성하고, PC 메신저 목록처럼 좌우에 별도 시간 열을 두지 않는다.

### 4-3. A03/B03 동일 대화

`A03`과 `B03`은 별도 원고가 아니라 하나의 공유 대화 데이터다.

- A폰: A 발신은 오른쪽, B 수신은 왼쪽
- B폰: B 발신은 오른쪽, A 수신은 왼쪽
- 본문, 첨부, 실제 시각은 완전히 동일
- 연락처 표기만 기기 소유자의 주소록 기준으로 다를 수 있음
- B폰의 `메시지 알림 끄기` 상태는 `B03-C1`에서 확인 가능
- B는 A를 차단하지 않았으므로 사건 당일까지 같은 대화가 이어짐

메시지 원문은 v0.3 패킷의 7개 구간을 그대로 사용한다. UI 공간에 맞춘다는 이유로 문장을 줄이거나 새 문장을 만들지 않는다.

#### 대화·구간·메시지 ID

공유 원본과 기획상 참조를 분리한다.

- `threadId`: A/B 양쪽이 공유하는 원본 대화 ID
- `segmentId`: 같은 시점에 묶인 대화 구간 ID
- `messageId`: 개별 메시지의 고유 ID
- `evidenceRefs`: A03/B03 등 증거 마스터표와 연결하는 참조 목록
- `sortKey`: 같은 시각의 항목을 포함해 표시 순서를 결정하는 별도 값

`threadId`, `segmentId`, `messageId`는 한 번 발급하면 콘텐츠를 삽입·재정렬해도 바꾸지 않는 불변 키다. 배열 인덱스, “세 번째 구간”, “네 번째 메시지”, 본문, 시각, 인물명, 파일 경로에서 ID를 계산하지 않는다. Unity의 기존 데이터 방식에 맞춘 직렬화 GUID 또는 동등한 안정 키를 사용한다.

`A03-03`, `A03-03-04` 같은 표기는 현재 정렬 결과를 사람이 읽기 좋게 보여주는 **에디터·검수용 위치 표기**일 뿐 원본 ID가 아니다. 중간에 메시지가 추가되면 이 위치 표기는 바뀔 수 있지만 핀, 저장 데이터, `evidenceRefs`, 튜토리얼 참조는 불변 `segmentId`·`messageId`를 사용하므로 대상을 잃지 않아야 한다. 이 위치 표기도 실제 휴대전화 화면에는 노출하지 않는다.

각 메시지는 상대 날짜와 시각을 직접 가진다. 구간 번호나 배열 순번에서 분 단위 시각을 자동 생성하지 않는다. 같은 분에 여러 메시지가 있으면 동일 시각과 별도의 `sortKey`로 순서를 정하고, `sortKey`가 바뀌어도 `messageId`는 유지한다.

공유 대화 전체에는 `A03`, `B03` 참조를 연결하고, 사건 당일 구간에는 같은 불변 `segmentId`에 `A12`, `B15` 참조도 함께 연결한다. A12/B15를 별도의 대화나 복제 메시지로 만들지 않는다.

### 4-4. 메시지 검색

메시지 앱 내부 검색은 현재 기기에 실제로 존재하는 다음 표시 정보만 찾는다.

- 대화 상대
- 메시지 본문
- 표시 날짜

내부 증거 ID, 작가용 메모, 후반 결론은 검색되지 않는다. 검색 결과를 누르면 해당 대화의 해당 위치로 이동하되 새로운 데이터를 해금하지 않는다.

## 5. 다른 휴대전화 앱

메시지 앱의 구조가 확정된 뒤 같은 원칙으로 확장한다.

### 5-1. 사진

기본 흐름:

1. 최근 항목 또는 앨범 목록
2. 사진 그리드
3. 사진 한 장 전체 보기
4. 앞/뒤 사진 이동

휴대전화 안에는 파일명과 증거 ID를 항상 크게 노출하지 않는다. 기본 갤러리에서는 사진과 촬영 날짜가 중심이고, 파일명·정확한 경로·해시·복구 상태는 우측 업무 패널에서 본다.

A01 사진 18장은 별도 사건 폴더가 아니라 일반 갤러리 시간순 목록에 일상 사진과 섞는다. B01도 B의 평범한 일상 사진처럼 보인다. 자동으로 같은 인물이라고 표시하지 않는다.

### 5-2. 브라우저

다음 중 데이터 종류에 맞는 모바일 브라우저 화면을 사용한다.

- 열려 있던 탭
- 방문 기록
- 검색 기록
- 저장된 페이지 또는 다운로드

A02와 B02의 검색 문구를 증거 카드 표로 만들지 않는다. 실제 브라우저 방문·검색 목록 속에서 날짜순으로 보이게 한다.

### 5-3. 지도/위치

- 최근 검색 장소 목록
- 경로 조회 기록
- 위치 공유 메시지에서 열린 지도 핀
- 사건 당일 SH01 위치 기록

`D-5`, `SH01` 같은 내부 이름은 지도 화면에 쓰지 않는다. 지도 안에는 실제 장소명·시각·핀만 표시하고 업무 패널에서 내부 ID를 보여준다.

### 5-4. 파일

- 일반적인 폴더 구조
- 파일명, 수정 시각, 썸네일
- 다운로드/백업/임시 폴더
- 상세 파일 열람

`증거`, `피해자`, `유포용`, `범죄 자료`처럼 의미를 설명하는 폴더명을 새로 만들지 않는다. B13도 v0.3 규칙대로 평범한 임시·백업 위치 안에서 발견되어야 한다.

### 5-5. 설정·계정 상태

SNS 비공개 전환, 메시지 알림 끄기, 연동 계정 상태는 실제 설정 화면이나 설정 변경 기록처럼 보여준다. 사건 설명용 보고서 카드로 대체하지 않는다.

## 6. 화면 상태 3종

### 6-1. 일반 작업 화면

- 좌측: 의뢰·앱 전환
- 중앙: 휴대전화 원본 화면
- 우측: 작업메모와 최소 메타데이터

게임 시간의 대부분을 차지하는 기본 상태다.

### 6-2. 상세 보기

현재 앱의 원본 표현을 유지하면서 한 기록을 더 크게 본다.

- 메시지: 해당 대화 위치로 이동하고 선택 메시지에만 약한 포커스
- 사진: 모바일 갤러리의 한 장 보기
- 브라우저: 선택 방문·페이지 상세
- 파일: 파일 미리보기
- 우측: 정확한 시간, 경로, 출처, 복구 상태 등 메타데이터 확장

상세 보기가 별도의 포렌식 표 화면으로 갑자기 바뀌지 않게 한다.

### 6-3. 비교 모드

비교 모드는 휴대전화 앱 자체가 아니라 PC 업무 도구다. 여기서는 기기 프레임을 잠시 벗어나도 된다.

- 핀한 두 항목을 같은 크기의 좌우 패널에 표시
- 각각의 의뢰 표시명·기기 소유자 이름, 앱, 출처, 시각, 내부 ID를 명확히 표시
- 원문·이미지를 가능한 한 원본 렌더링으로 유지
- 어느 쪽이 정답인지 자동 판정하지 않음
- 무관한 두 항목도 비교 가능
- `CROSS-1` 등은 기획된 시점 전까지 자동 일치나 완료 표시가 없음

비교가 끝나면 각 휴대전화의 이전 앱 위치를 유지한 채 일반 작업 화면으로 돌아간다.

## 7. 증거 선택·핀·비교

첨부 UI 시안의 선택 사각형과 떠 있는 설명 말풍선은 방향 참고용일 뿐 최종 규칙이 아니다.

### 7-1. 기본 상태

- 휴대전화 원본 화면에 선택 테두리나 증거 ID를 상시 표시하지 않는다.
- 플레이어는 먼저 기록을 평범하게 읽는다.
- 바깥 툴바의 `핀` 또는 `기록 선택`을 눌렀을 때만 선택 모드에 들어간다.

### 7-2. 선택 단위

앱별 선택 단위:

| 앱 | 선택 단위 |
| --- | --- |
| 메시지 | 개별 메시지, 첨부, 위치 공유 또는 대화방 전체 |
| 사진 | 사진 한 장 |
| 브라우저 | 방문/검색 기록 한 행 또는 열린 페이지 |
| 지도 | 장소·경로·위치 기록 한 건 |
| 파일 | 파일 한 개 |
| 설정 | 설정 변경 기록 한 건 |

### 7-3. 선택 피드백

- 선택 가능한 항목에 마우스를 올리거나 키보드 포커스를 주면 얇은 강조만 표시
- 선택하면 원본 콘텐츠 가장자리에 작은 체크 또는 핀 표시
- 긴 설명 말풍선을 휴대전화 위에 겹쳐 띄우지 않음
- 선택 결과와 내부 ID는 우측 업무 패널에 추가
- 선택 모드를 끝내면 휴대전화 화면은 다시 깨끗한 원본 상태로 복귀

메시지 여러 개가 하나의 기획 증거 구간을 이룰 때는 개별 메시지 ID와 구간 ID를 데이터에서 구분한다. 플레이어가 한 메시지만 핀할 수 있고, 필요하면 우측 패널에서 `이 구간 전체`를 추가할 수 있게 한다. 휴대전화 위에 ID 말풍선을 띄우지 않는다.

### 7-4. 핀과 분류 분리

- 핀: 다시 보거나 비교하기 위한 임시 업무 기록
- 보존 후보: 최종 보존 검토 대상
- 삭제 후보: 최종 삭제 검토 대상
- 열람 여부: 한 번 열어본 상태

네 상태를 하나의 `selected` 값으로 합치지 않는다.

## 8. 검색과 업무 상태

상단의 전역 검색은 현재 접근·인덱싱된 자료만 검색한다.

- 화면에 실제로 보이는 문구
- 파일명
- 대화 상대
- 날짜
- 장소명

검색은 새로운 자료를 생성하거나 잠금 해제하지 않는다. 클라우드가 아직 동기화되지 않았다면 그 자료는 결과에 나오지 않는다.

업무 알림은 다음처럼 건조하게 쓴다.

- `{caseDisplayName} 의뢰 — 연동 데이터 확인 완료`
- `새 백업 데이터 인덱싱 완료`
- `보존/삭제 미분류 항목 25개`

다음 표현은 쓰지 않는다.

- `새로운 단서를 찾았습니다`
- `B가 수상합니다`
- `A폰으로 이동하세요`
- `두 사건이 연결되었습니다`

## 9. 시각·음향 방향

### PC 업무 프로그램

- 차갑고 절제된 다크 테마 또는 저채도 중성 테마
- 촘촘하지만 읽기 쉬운 업무용 정보 밀도
- 장식보다 상태·출처·조작이 우선
- 과도한 네온, 글리치, 해킹 연출 금지
- 사건의 감정을 UI 색으로 미리 판정하지 않음

### 휴대전화

- 업무 프로그램보다 더 익숙하고 인간적인 모바일 비율과 여백
- 실제 앱과 유사한 상태바, 헤더, 목록, 말풍선, 뒤로가기
- A/B의 기록은 같은 UI 안에서 평범한 개인 생활처럼 보임
- 핵심 증거만 특별한 색으로 칠하지 않음
- 앱 전환·대화 진입·사진 넘기기에 짧고 자연스러운 모바일 전환 사용
- 실제 인물 이름·연락처 저장명·단체방 제목·대화 본문에는 일반 UI 글꼴을 사용하고, 고정폭 글꼴은 ID·해시·기술 로그·정렬이 필요한 시각 값에만 제한한다.
- 날짜 구분선과 개별 시각은 하나의 로케일 규칙을 사용한다. `오후 9:18`과 `21:18`을 한 화면에서 섞지 않는다.

### 소리

새 메시지가 실제로 도착하는 장면이 아니라면 알림음을 남발하지 않는다. 기본은 클릭, 뒤로가기, 핀, 분류 같은 약한 업무 피드백만 둔다. 공포 효과음이나 점프스케어는 사용하지 않는다.

## 10. 구현 구조 원칙

현재 Unity 프로젝트 구조와 기존 UI 방식을 먼저 확인하고 거기에 맞춘다. 아래 명칭은 역할 설명이며 기존 프로젝트의 네이밍을 무시하고 새 구조를 강제하는 규칙이 아니다.

### 분리해야 하는 상태

1. 원본 기록 데이터
2. 현재 접근 가능 여부와 인덱싱 상태
3. 휴대전화 앱의 표시·탐색 상태
4. 플레이어의 핀·메모·분류 상태
5. 비교 화면 상태

원본 기록 객체에 `isSuspicious`, `correctEvidence`, `culprit` 같은 정답 필드를 UI 판정용으로 넣지 않는다.

### 확장 가능한 메시지 데이터

현재 프로젝트에 이미 데이터 계층이 있다면 그 구조를 우선 사용한다. 새 구조가 필요할 때도 특정 대화방 개수나 특정 메시지 위치에 의존하지 않는다.

대화방에는 최소한 다음 역할의 필드가 필요하다.

- 공유 원본 대화 ID
- 참여자 ID와 기기별 연락처 표시명
- 메시지 배열
- 알림·읽지 않음 등 실제 설정 상태
- 접근 가능 시점과 출처
- 마지막 메시지에서 계산되는 목록 미리보기와 정렬용 시각

개별 메시지에는 최소한 다음 역할의 필드가 필요하다.

- 고유 메시지 ID
- 발신자 ID
- 상대 날짜와 분 단위 시각
- 같은 시각 안의 별도 정렬값
- 본문
- 선택적 첨부·위치·자산 참조
- 구간 ID와 증거 참조

`저장되지 않은 번호`, 특정 인물 이름, 관계명, 단체방 제목이나 미리보기 문장을 목록 프리팹 안에 직접 넣지 않는다. 데이터 파일 또는 기존 콘텐츠 저장소에 대화방을 추가하면 같은 렌더러가 자동으로 목록과 상세 화면을 만들어야 한다.

내부 역할 키와 플레이어 표시명도 분리한다. 내부 참여자 ID가 B여도 P0 A폰의 `contactDisplayName`은 `저장되지 않은 번호`일 수 있다. 반대로 이름이 저장된 친구의 `contactDisplayName`은 실제 이름 또는 자연스러운 저장명이어야 하며 `친구`라는 관계 분류로 대체하지 않는다. 검색과 화면 제목은 당시 기기에 실제로 저장된 표시명과 현재 진행 단계에서 허용된 정보만 사용한다.

### 모든 콘텐츠와 UI 문구의 데이터화

하드코딩 금지는 메시지에만 적용하지 않는다.

- 사진, 브라우저 기록, 지도·경로, 파일, 설정 로그, 계정 기록에도 불변 `recordId`와 별도 `sortKey`를 둔다.
- 사진과 첨부 자산은 불변 `mediaAssetId`로 연결하고 배열 위치나 파일 경로를 참조 키로 쓰지 않는다.
- 의뢰 요청문, 업무 알림, 우측 패널 라벨, 프로그램 이름, 빈 상태 문구, 오류 문구는 중앙 UI 문자열 테이블 또는 기존 현지화 체계에서 읽는다.
- 업무 알림은 `{caseDisplayName}`, `{count}` 같은 토큰을 받는 템플릿으로 만들고 `의뢰 A` 같은 완성 문장을 코드에 넣지 않는다.
- 앱 표시명·순서·아이콘·공개 조건은 앱 등록 데이터에서 관리한다.
- 목록 수, 미리보기, 파일명, 날짜, 분류 상태는 현재 로드된 원본 기록에서 계산한다.
- 화면에 보이는 문자열을 변경하기 위해 씬·프리팹·스크립트를 수정하지 않아도 되는 구조를 기본으로 한다.

### 참조 무결성과 삭제·이름 변경

핀, 비교, 보존·삭제 후보, 튜토리얼, 증거 참조, 첨부 연결, 저장 게임은 모두 불변 원본 ID를 저장한다. 표시 이름·본문·시간·정렬값을 바꿔도 참조 대상이 바뀌지 않아야 한다.

에디터 검증 도구를 두고 수동 실행과 빌드 전에 최소한 다음을 검사한다.

- 중복·비어 있는 `recordId`, `threadId`, `segmentId`, `messageId`, `mediaAssetId`
- 존재하지 않는 `evidenceRefs`, `parentId`, 참여자, 첨부, 자산, 앱, UI 문자열 키
- 핀·비교·T01/T02 튜토리얼이 가리키는 대상 누락
- 메시지·기록을 정렬한 뒤 발생하는 시각 역전 또는 필수 정렬값 충돌
- 같은 원본이어야 하는 A03/B03 본문·시각·첨부의 복제 또는 불일치
- 현재 진행 단계에서 허용되지 않은 표시명·미래 정보가 검색·제목에 노출되는 문제

참조 중인 항목을 편집기에서 삭제하려 하면 오류로 막거나 참조 목록을 보여주고 명시적인 마이그레이션을 요구한다. 이미 저장 게임에 사용될 수 있는 ID는 바로 재사용하지 않고 비활성·폐기 상태로 남긴다. 불가피하게 ID를 바꾸면 이전 ID에서 새 ID로 연결하는 별칭·마이그레이션 표를 둔다. 이름 변경은 표시 데이터만 바꾸며 원본 ID에는 영향을 주지 않는다.

### 필요한 동작

- A/B별 앱 탐색 스택 저장
- 앱 목록 → 상세 → 뒤로가기
- 내부 상대 날짜 → 실제 표시 날짜 변환
- A03/B03 공유 대화의 발신·수신 방향 반전
- 표시 텍스트 기반 검색
- 어떤 기록이든 핀 가능
- 핀한 두 기록 비교
- 핀/보존/삭제/열람 상태 독립 저장
- 로컬/클라우드/연동 접근 상태 반영
- 더미 데이터와 핵심 증거의 동일 렌더링

### 데이터 중복 금지

- A03과 B03의 메시지 본문을 두 벌로 작성하지 않음
- 메시지 첨부와 갤러리 저장본이 같은 자산이면 내부 `mediaAssetId` 공유
- `D-14`와 실제 날짜 문자열을 별도로 하드코딩하지 않음
- 불변 원본 ID와 표시 순서·위치 표기를 분리
- 핀·저장·증거·튜토리얼 참조는 불변 ID만 사용
- 목록 미리보기와 상세 본문을 서로 다른 문장으로 작성하지 않음

## 12. UI-01 완료 기준

첫 구현은 아래 항목을 모두 만족해야 완료다.

- [ ] 휴대전화 상태바·앱 헤더·뒤로가기·대화 목록·말풍선·입력창이 있음

- [ ] A03 본문은 v0.3 원문과 동일함
- [ ] 발신/수신 방향이 A폰 기준으로 맞음
- [ ] 휴대전화 안에는 증거 ID와 `D-14`가 보이지 않음

- [ ] 우측 업무 패널에는 기록 ID A03, 확정된 기기 소유자 이름, 출처, 사망일 기준 기록 시점·기간을 표시할 수 있음
- [ ] 일상 대화가 A03과 같은 목록·상세 컴포넌트를 사용함
- [ ] 핵심 대화만 특별한 색이나 경고 표시를 사용하지 않음

- [ ] 더미 대화방 하나를 데이터에 추가했을 때 UI 코드 수정 없이 목록과 개수가 갱신됨
- [ ] 기존 메시지 사이에 새 메시지를 넣어도 기존 핀·증거 참조가 같은 `messageId`를 가리킴
- [ ] 메시지마다 상대 날짜·시각·같은 시각 내 정렬값이 별도 저장됨
- [ ] 시안의 실제 날짜와 앱 개수가 하드코딩돼 있지 않음
- [ ] 목록의 오늘·어제·요일 표기는 PC 날짜가 아니라 `caseDate`를 기준으로 계산됨
- [ ] 검색 안내 문구가 입력 영역 밖으로 밀려나지 않음
- [ ] 휴대전화 안의 날짜·시각 표기 형식이 통일됨
- [ ] 이름에는 일반 UI 글꼴, ID·기술값에는 필요한 경우에만 고정폭 글꼴을 사용함
- [ ] 기기 프레임 때문에 메시지 글자가 너무 작아지지 않음
- [ ] 16:9 PC 화면에서 좌·중·우 영역이 겹치지 않음
- [ ] 아직 없는 기능의 버튼이 작동하는 척하거나 가짜 성공 상태를 만들지 않음

### UI-01에서 만들지 않는 것

- 사진·브라우저·지도·파일의 완성 구현
- 얼굴 자동 일치
- CROSS 판정
- 사건 해설
- 최종 삭제 화면
- 모든 진행 단계
- 이미지 시안의 임시 증거 선택 말풍선 복제
- 임의의 읽지 않음 숫자와 임의의 앱별 데이터 개수
- `A03 · B와의 메시지`, `플레이어 메모`, `기획 시점` 같은 게임 밖·스포일러성 문구

## 13. 전체 UI 검수 체크리스트

### 몰입

- [ ] 휴대전화 안쪽과 업무 프로그램 바깥쪽의 정보 문법이 분리돼 있음
- [ ] 플레이어가 목록을 거쳐 기록을 직접 찾음
- [ ] 핵심 증거가 일반 데이터와 같은 방식으로 보임
- [ ] 실제 앱처럼 뒤로가기와 이전 위치 복원이 됨
- [ ] 새 대화방과 메시지를 데이터만으로 추가할 수 있음
- [ ] 작가용 인물명과 플레이어에게 보이는 연락처명이 분리돼 있음
- [ ] 이름이 있는 친구·가족·담당자는 실제 이름 또는 저장명으로 보이고 관계 분류가 연락처명으로 노출되지 않음

### 기획 일관성

- [ ] A/B 메시지는 같은 원본 데이터를 공유함
- [ ] B는 A를 차단하지 않고 알림만 끈 상태임
- [ ] A01 18장은 일반 사진 사이에 흩어져 있음
- [ ] B01은 SNS 프로필이 아니라 로컬 갤러리 일상 사진임
- [ ] P2 이전에 A06/B07 자동 일치가 뜨지 않음
- [ ] D01 자료는 `D01-01~05`, `parentId: A06`을 사용함
- [ ] 사건의 미확정 요소를 UI 문구가 임의로 확정하지 않음

### 업무 도구

- [ ] 핀·열람·보존·삭제 상태가 분리돼 있음
- [ ] 무관한 자료도 핀·비교 가능함
- [ ] 검색이 현재 접근 가능한 표시 데이터만 필터링함
- [ ] 비교 화면이 정답을 대신 말하지 않음
- [ ] 동기화 상태가 실제 데이터 접근 범위와 일치함
- [ ] 사진·브라우저·지도·파일·설정도 메시지와 같은 불변 ID·정렬·검증 원칙을 사용함
- [ ] 삭제 또는 이름 변경 뒤 끊긴 참조·중복 ID·시간 역전을 검출할 수 있음
- [ ] 업무 문구·프로그램명·앱 등록 정보가 코드와 프리팹에 흩어져 있지 않음

### 접근성과 가독성

- [ ] 휴대전화 본문 글자가 PC 화면에서 읽을 수 있음
- [ ] 색만으로 발신/수신·선택·상태를 구분하지 않음
- [ ] 키보드로 목록 이동, 열기, 뒤로가기, 핀이 가능함
- [ ] 선택 포커스가 보이지만 원본 기록을 과도하게 가리지 않음
- [ ] 축소된 창에서도 핵심 조작이 잘리거나 겹치지 않음

## 14. 클로드에게 전달할 UI-01 구현 지시문

```text
교차점의 UI를 한 번에 전부 만들지 말고 UI-01만 구현해줘.

먼저 현재 Unity 프로젝트의 버전, 폴더 구조, 기존 UI 방식과 이미 구현된 범위를 확인해. 기준 문서는 Docs/GameDesign.md, Docs/교차점_초반데이터_제작패킷_v0.3.md, Docs/교차점_UI_제작패킷_v0.1.md야. 함께 첨부한 UI 시안 이미지는 분위기와 좌·중·우 구조, 휴대전화 원본 화면의 느낌을 참고하되 픽셀 단위로 복제하지 마. 시안 속 증거 선택 사각형과 떠 있는 A03-03 말풍선은 임시 표현이므로 이번 단계에서 구현하지 마.

이번 작업 범위는 상단 업무 바, 좌측 의뢰·앱 영역의 기본 형태, 중앙 휴대전화 프레임과 A폰 메시지 앱, 우측 업무 기록 기본 패널까지야. A폰 메시지 앱에는 실제 휴대전화처럼 상태바, 메시지 대화방 목록, 검색창, 대화방 헤더, 뒤로가기, 발신·수신 말풍선, 날짜 구분, 읽기 전용 입력창을 만들어. 목록에서 A03 대화방을 열고 다시 목록으로 돌아갈 수 있어야 해. A03 문구는 v0.3의 7개 구간 원문을 하나의 공유 대화 데이터로 연결해. 화면에 보이는 날짜는 caseDate에서 계산하고 시안의 9월 22일·9월 26일을 상수로 넣지 마.

휴대전화 안에는 A03, D-14, P0, 필수 증거, 보존 후보 같은 업무·기획 정보를 표시하지 마. 휴대전화에는 당시 기기에 저장된 실제 인물 이름·연락처 저장명·단체방 제목, caseDate에서 계산된 실제 달력 날짜와 시각, 원래 메시지 본문만 보여. `친구`, `가족`, `아르바이트 담당자`, A/B/C/D 같은 기획상 관계·역할 분류를 연락처명으로 그대로 쓰지 마. 단, 실제로 그렇게 저장했다는 별도 데이터가 있으면 예외야. P0의 A폰에서 상대가 B라는 사실을 제목이나 검색 결과로 먼저 밝히지 말고 `저장되지 않은 번호와의 대화`처럼 현재 확인 가능한 정보만 사용해. 우측에도 `A03 · B와의 메시지`, `플레이어 메모`, `기획 시점` 같은 문구를 쓰지 말고 `기록 ID A03`, `저장되지 않은 번호와의 대화`, `작업메모`, `기록 기간/기록 시각`을 분리해 표시해. 화면에는 D-14 대신 `사망 14일 전`처럼 변환된 표현을 사용해. 핵심 대화에 경고색이나 수상함 표시를 붙이지 말고 일반 대화와 같은 컴포넌트를 사용해.

현재 데이터 구조를 최대한 재사용하고, 메시지 원본 데이터와 휴대전화 표시 상태, 플레이어 업무 상태를 분리해. 대화방 행, 연락처명, 단체방 제목, 목록 개수, 최신순 정렬, 마지막 메시지 미리보기, 날짜를 하드코딩하지 마. 현재 v0.3 데이터는 최소 시드 데이터일 뿐이고 이후 이름이 붙은 더미 인물·대화방·메시지를 추가할 예정이므로, 데이터에 항목을 추가하면 같은 UI가 자동으로 목록과 상세 화면을 생성해야 해. 목록 미리보기는 실제 마지막 메시지에서 만들고 한 줄 말줄임으로 처리해. 읽지 않음 데이터가 없다면 `< 7` 같은 숫자를 만들지 마.

대화방·구간·메시지와 사진·브라우저·지도·파일·설정 기록에는 배열 위치와 무관한 불변 원본 ID를 발급해. `A03-03-04` 같은 순서형 표기는 에디터용 위치 표시일 뿐 핀·저장·증거·튜토리얼 참조에 쓰지 마. 메시지마다 상대 날짜, 분 단위 시각, 같은 시각 내 정렬값을 직접 저장하고 배열 순번으로 시각을 만들지 마. 삭제·이름 변경·중간 삽입 후에도 참조가 유지되어야 해. 중복 ID, 끊긴 evidenceRefs/mediaAssetId/튜토리얼 참조, 시각 역전을 검사하는 에디터 검증과 빌드 전 검사를 마련해.

임시 caseDate는 프로젝트 설정 한 곳에만 두고 날짜는 caseDate와 상대 시점에서 변환해. 시안 날짜나 화면별 날짜 문자열을 중복 하드코딩하지 마. 상태바 시계는 PC의 현재 현지 시각을 별도 시계 공급부에서 받아 표시하고 메시지 시각·caseDate·게임 진행에 연결하지 마. 메시지 목록의 오늘·어제·요일은 caseDate를 기준으로 계산해. 공유 대화 전체에는 A03/B03, 사건 당일 구간에는 A12/B15 참조를 연결하되 원본 대화를 복제하지 마.

의뢰 요청문, 업무 알림, 우측 패널 라벨, 프로그램 이름, 앱 표시명·순서·아이콘은 코드나 프리팹 문구가 아니라 중앙 문자열·앱 등록 데이터에서 읽어. 사진·브라우저·지도·파일 완성 구현, 증거 선택, 비교 모드, 자동 일치, CROSS 판정, 최종 삭제 화면은 이번 작업에 포함하지 마. UI-01에서 아직 없는 선택·비교 버튼은 숨기거나 명확히 비활성화하고, 비교 기능의 최종 버튼 명칭은 중립적인 `비교`를 사용해.

구현 후 변경 파일, 실행 방법, UI-01 완료 기준별 통과 여부, 아직 플레이스홀더인 부분을 보고해. 가능하면 16:9 화면 캡처도 함께 보여줘. UI-01이 검수되기 전에는 UI-02로 넘어가지 마.
```

## 현재 결론

교차점의 UI는 “포렌식 데이터베이스를 보는 게임”보다 **업무 프로그램을 통해 남의 휴대전화를 직접 열어보는 게임**에 가까워야 한다. 증거 해석과 분류는 바깥 업무 도구가 담당하고, 개인 기록 자체는 끝까지 실제 휴대전화 앱처럼 평범하게 남겨 둔다.
