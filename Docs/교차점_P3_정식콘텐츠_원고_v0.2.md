## 0. 이 원고의 고정 규칙

### 0-1. P3 도달 상한

P3 자료를 모두 읽은 플레이어가 도달할 수 있는 최대치:

1. 윤서하는 정유진의 원본 착장 사진(B07)을 가지고 있었다. (P1부터 알 수 있음)
2. 그 원본과 `daylog_041` 게시물(A06-02) 사이에, 윤서하 클라우드에 **크롭과 얼굴 스티커가 들어간 중간본**(B08)이 있다. 중간본은 게시 전날 만들어졌고, 기기에서는 지워졌지만 자동 백업 사본이 클라우드에 남아 있다.
3. 윤서하의 연동 브라우저 기록에 `daylog_041`이 두 번 남아 있다(B09: 검색 한 번, 방문 한 번). 둘 다 열람·검색 흔적일 뿐 소유 기록이 아니다.
4. 사건 당일 서지훈의 메시지가 오가던 10분 남짓 사이에 윤서하의 클라우드 백업 대상 변경·휴지통 비우기·기기 계정 연결 해제가 몰려 있다(B16). 무엇이 바뀌고 지워졌는지는 보이지 않는다.
5. 그래서 **지워진 데이터를 복구해 봐야 한다.**

P3 어디에도 다음은 없다: 윤서하가 계정을 운영했다는 문장, 계정 로그인·비밀번호·복구 정보, 여러 익명 계정의 동일 운영자 표시, 강나린·미상 인물의 자료, 삭제·변경된 항목의 이름·내용·개수, 서지훈이 마지막에 찾은 것, 폐상가 내부, 경찰 수사 범위.

### 0-2. 화면 문구 금지어

P2 원고 0-2를 그대로 따른다. 플레이어가 읽는 모든 문구(파일명, 미리보기, 검색어, 설정 값, 페이지 제목)에 다음을 쓰지 않는다.

- 결론형: `피해자`, `가해자`, `동일범`, `범인`, `정답`, `증거`, `유포`, `범죄`, `운영자`
- 장치형 파일명 금지: `victim`, `upload`, `anonymous`, `edit`, `유포`, `피해자`
- B13 구조 선노출 금지: `temp`, `edit`, `export`, `cache`, 날짜 폴더명
- 내부 표기: A/B/C/D/E, 증거 ID, `D-182` 같은 상대 날짜, `P3`, 불변 ID, 자산 ID(`c-b08-01` 등), 작가 메모
- 대본형 문장: `거의 다 들켰어`, `흔적을 지워야 해`, `이제 아무도 못 찾을 거야`, `증거를 전부 삭제했다`처럼 행동을 설명하는 문장. **P3에는 윤서하가 직접 쓴 문장이 하나도 없다** (자료는 파일·사진·검색어·방문 제목·설정 값뿐).

### 0-3. 날짜·시각

- 모든 기록 시각은 내부 `time.dayOffset`/`hour`/`minute`(사망일 기준 상대 날짜)로 저장한다. 화면은 기존 규칙대로 `사망 182일 전`, 달력 날짜는 `caseDate`에서 계산한다.
- **익명 게시물의 분 단위 게시 시각은 확정하지 않는다.** P2 원고의 값은 `D-181 23시 무렵`이다. A06-02 캡처(D-180 14:35)의 `15시간` 표시는 15시간 이상 16시간 미만이므로 게시는 D-181 22:36~23:35 사이 어딘가다. 이 원고의 기록은 이 범위와 겹치지 않게 앞(B08) 또는 뒤(B09-1)에 둔다.
- 이번 원고의 `visibleText`에는 달력 날짜가 필요한 줄이 없다. `{date:N}` 토큰은 쓰지 않는다.
- 이미지(B08, 일반 사진 2장)에는 글자가 없다.

### 0-4. 출처와 접근

| 출처 | 쓰는 자료 | 화면 위치 |
| --- | --- | --- |
| 클라우드(`source: Cloud`) | 사진 자동 백업 중 기기에서는 지워진 사진 3장, `Documents`·`Download` 백업 파일 5개 | 사진 앱 `최근 항목`(클라우드 배지), 파일 앱 `클라우드` 위치 |
| 연동(`source: Linked`) | 계정에 동기화된 브라우저 기록 5건, 계정·클라우드·알림 설정 변경 5건 | 브라우저 앱(연동 배지), 설정 앱 `변경 기록` |

- 모두 기기 = 윤서하 의뢰, `availableFrom: P3`. `Job_B_Inventory`의 `unlocksSources`(Cloud·Linked)와 완료 단계(P3)에 맞는다(검증 도구 `CheckSource` 기준).
- 같은 사진의 기기 사본과 클라우드 사본을 둘 다 만들지 않는다. **클라우드 사진 = 기기에서는 지워져 자동 백업 사본만 남은 사진**이다. 그래서 이 3장은 모두 같은 상태 표시 `클라우드에만 있음`을 가진다. B08만 다른 표시를 갖지 않는다.

### 0-5. 원고 ID와 화면 기록 코드

- `P3-B08`, `P3-G01` 같은 원고 ID는 이 문서와 작가 메모에서만 쓴다.
- 런타임 불변 ID는 에셋 생성 때 새로 발급한다(순서·이름과 무관).
- 화면의 `기록 ID`는 기존 규칙대로 불변 ID + 기기 ID로 계산한 중립 코드(`RecordCode`)다. 원고 ID·증거 ID는 화면에 나오지 않는다.

### 0-6. 이미지

- 새로 그리는 사진은 일반 사진 2장(P3-G01·G02)뿐이다. 둘 다 사람·글자가 없는 생활 사진이다.
- B08은 **이미 있는 파생 자산 `Assets/Art/Photos/Derived/c-b08-01.png`**를 쓴다(B07 실제 원본 `c-outfit-01`에서 크롭·스티커로 만든 파일, 2026-10-13 재생성). `c-post-01`도 그대로 둔다. 새로 생성하지 않는다(결정됨).

## 10. 현지화 준비

- 이미지 3장(B08·G01·G02)에 글자가 없다. 모든 글자는 Unity 텍스트(데이터·문자열 테이블)다.
- 파일명·검색어·방문 제목·설정 라벨·설정 값·파일 미리보기는 **기록 데이터 값**이라 문자열 키가 아니다. 지금 구조에는 기록 데이터의 언어별 값이 없다. **결정 C에 따라 콘텐츠 현지화 기반을 P3 기록보다 먼저 구현했다(15-2절).** 에셋의 한국어 원문이 기본값이고, 언어별 콘텐츠 번역 테이블이 `콘텐츠 불변 ID:필드 키`로 선택적으로 덮어쓴다. P0~P2 기록도 같은 구조를 쓰며 내용은 바뀌지 않았다. 글자가 들어간 캡처 이미지는 영어판에서 캡처 렌더러로 다시 렌더링한다(P3에는 해당 이미지 없음).
- 원고 확정 당시에는 영어 번역을 범위에서 제외했으나, 이후 현재 P0~P3의 텍스트 기반 자료와 공통 UI를 대상으로 영문 1차 현지화를 추가했다. 글자가 들어간 기존 P2 캡처 이미지는 여전히 별도 과제다.
- 고정 폭·강제 줄바꿈을 전제한 문장 없음. 파일 미리보기의 줄은 작성자가 나눈 문단(목록 항목)뿐이다.
- 성별·조사 문제: 이번 원고의 플레이어용 문장에는 인물 이름·대명사·조사 결합(`{name}이/가`)이 없다. 숫자·시간이 붙은 값(`31,500원`, `23:00~07:00`, `2~3일`, `30분`, `2시간`, `4층`)은 언어마다 형식이 달라 값 통째로 번역해야 한다(표시). B16 값에는 숫자가 없다.
