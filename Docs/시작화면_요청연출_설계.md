# 시작 화면·유족 요청 도입 장면 설계

갱신: 2026-10-18

Main 씬 하나 안에서 타이틀과 유족 요청 도입 장면을 엔딩(`EndingSceneView`)처럼 업무 UI 전체를 덮는 전체 화면으로 보여준다. 별도 씬·UI 프레임워크는 없다. 두 화면은 씬에 미리 두지 않고 실행 중 루트 캔버스 맨 위에 만들었다가 닫을 때 지운다(빌더 변경 없음).

## 1. 시작 흐름

| 저장 상태 | 판정 | 타이틀 메뉴 | 결과 |
| --- | --- | --- | --- |
| 저장 없음 | 진행 저장 파일이 없거나 시작 단계 그대로 아무 진행이 없음(새로 시작하기 직후), 업무 저장에 비어 있지 않은 항목·비교 이력 없음 | 시작하기 / 종료 | 업무 배정 안내 → 서지훈 유족 요청 장면 → P0 업무 화면 |
| 진행 중 | 위가 아니고 처리 스냅샷 없음 | 계속하기 / 새로 시작하기 / 종료 | 기존 진행 복원. 지금 의뢰의 도입 요청을 아직 확인하지 않았으면 그 장면부터 |
| 처리 완료 | 진행 저장에 최종 처리 스냅샷 있음 | 처리 결과 보기 / 새로 시작하기 / 종료 | 저장된 스냅샷의 엔딩 마지막 화면(최초 연출을 아직 안 봤으면 그 연출) |

- 타이틀 표시만으로 요청 열람·작업 시작·진행 단계·엔딩 소개 상태를 바꾸지 않는다.
- 확인하지 않은 연락·최종 처리안·연동 결과 요약은 시작 화면을 닫은 뒤 기존 규칙대로 이어서 보여준다.
- 게임 중 최종 처리를 처음 완료했을 때의 엔딩 시퀀스는 그대로다. 재실행 뒤에는 타이틀의 `처리 결과 보기`를 거친다(P6 원고 12·13절 갱신).

## 2. 타이틀

- 엔딩과 같은 배경색(`stage`를 검정 쪽으로 62%), 글꼴, 색, 넓은 여백.
- 중앙 `교차점`(굵게 64), 아래 작게 `INTERSECTION`(자간 넓힘). 영어 화면은 `Intersection` 아래 작게 `교차점`.
- 제목 0.8초 페이드 뒤 메뉴가 0.45초 동안 나타나고, 다 나타난 뒤에만 클릭·선택을 받는다. 첫 항목이 선택돼 Enter로도 고를 수 있다.
- 사건 설명·문구·배경 이미지·음성 없음.

## 3. 새로 시작하기

- 저장이 있을 때만 메뉴에 있고, 누르면 확인 상자(메뉴는 숨김)를 연다. 기본 선택은 `취소`. 확인 상자가 떠 있으면 Esc는 취소다.
- 취소: 저장과 화면 상태를 바꾸지 않는다.
- 확인: `WorkStore.ResetAll`(열람·고정·분류·메모·비교 이력·예전 튜토리얼 단계) → `ProgressStore.ResetAll`(단계·작업·효과·알림·요약·처리안·스냅샷·엔딩 소개, 한 트랜잭션).
  - 업무 저장 실패: 메모리를 되돌리고 타이틀에 실패를 알린다(저장 파일 그대로).
  - 진행 저장 실패: 진행은 트랜잭션이 되돌리고, 업무 저장은 이전 상태를 다시 저장한다. 타이틀에 남는다.
  - 성공: 같은 씬을 다시 열어 화면·탐색 상태를 처음부터 만들고, 타이틀 없이 업무 배정 안내 → 첫 요청 장면으로 간다.
- 언어·표시 설정은 저장 파일과 별개(`GameConfig`)라 그대로다. 저장 폴더 전체 삭제 같은 처리는 하지 않는다.

## 4. 업무 배정 안내

- 새 게임에서만(시작하기, 새로 시작하기 확인 뒤) 서지훈 유족 요청 앞에 한 번 보여준다. 계속하기에는 소급하지 않는다.
- 요청 장면과 같은 `RequestSceneView`(배경·글꼴·배치·문장 페이드·버튼)를 쓴다. 상단 `업무 배정 안내`, 버튼 `요청 확인하기`.
- 문구는 UI 문자열(`briefing.heading`·`briefing.body`·`briefing.confirm`, 한국어·영어)이다. 의뢰·요청 레코드나 진행 조건이 아니다.
- 두 의뢰가 접수됐다는 사실만 알린다. 두 사람의 관계·같은 사망일과 장소·사건 내용은 공개하지 않는다. B 자료의 접근 시점(P1)은 그대로다.
- 버튼은 서지훈 유족 요청 장면으로 넘어갈 뿐, 요청 열람·분류·작업 시작을 기록하지 않는다. 확인 전에 종료하면 저장이 없으므로 다음 실행도 시작하기 → 안내부터다.

## 5. 유족 요청 도입 장면

- 대상은 데이터로 정한다: `WorkRequestData.introScene`. 현재 `Request_A_T01`, `Request_B_ORD`만 켜져 있다. 런타임에서 인물명·파일명·GUID로 분기하지 않는다.
- 상단 작게 `{case} 유족의 요청`(의뢰 표시명). 본문은 `WorkRequestData.Body`(현재 언어)를 그대로 쓴다. 화면 코드에 사본이 없다.
- 표시용 분절만 한다.
  - 본문 줄 중 `introDetailFromLine`(B는 3) 이후는 작은 글씨 부가 정보(`정리 대상`·기기·계정)로 한 묶음.
  - 주요 줄은 문장 끝(`. ! ? 。`) 뒤 공백에서 나눠 순서대로 페이드하고 앞 문장은 남긴다.
- 자동으로 넘어가지 않는다. 본문이 다 나타난 뒤 `확인하고 시작` 버튼이 생긴다.
- 버튼: 기존 요청 열람(`WorkStore.MarkViewed(RecordRef.ForRequest)`)만 기록하고 업무 화면으로 돌아간다. 분류·인벤토리 시작·연동을 자동 실행하지 않는다. 가족사진 보존 지정은 플레이어가 업무 화면에서 한다(A 인벤토리 시작 조건 `요청 열람 + 가족사진 보존` 유지).
- 확인 전에 종료하면 요청은 미열람으로 남고, 다음에 그 의뢰를 검토할 때 다시 나온다.

### 표시 시점

- A: 새 게임(시작하기·새로 시작하기 직후), 또는 계속하기에서 지금 의뢰의 도입 요청이 미열람일 때.
- B: 기존 접근 시점(P1)은 그대로다. 업무 중 지금 의뢰가 바뀌어 그 의뢰에 미열람 도입 요청이 있으면 다음 프레임에 보여준다(좌측 선택·원본 열기·요약 이동 등 경로와 무관).
  - 다른 전체 화면(비교·작업 시작 연출·연동 요약·P6 화면)이 떠 있으면 미룬다.
- 소급하지 않음: 실행 시작 때 요청은 미열람이지만 그 의뢰의 작업이 이미 시작됐거나 그 기기 기록을 열람한 기존 저장이면, 그 실행에서는 도입 장면을 띄우지 않는다.
- 업무 중 요청을 다시 열면 기존 요청 패널을 쓴다. 이미 읽은 요청은 도입 장면을 반복하지 않는다.
- P6 유족 연락은 대상이 아니다.

## 6. 입력 차단

- 루트가 화면 전체의 마우스 입력을 받고, 상단·좌우 패널은 기존 `SetPresentationInputBlocked`로 막는다. 열 때 열린 팝업·고르기·검색·작업함을 닫는다.
- 시작 화면이 떠 있으면 `AppShell.Update`는 그 화면만 갱신한다. 업무 단축키·Esc·휴대전화 조작·P6 자동 개방이 없다.
- 시작 화면을 연 프레임의 입력은 받지 않는다. 요청 장면 버튼은 본문이 다 나타난 뒤에만 생긴다. 앞 화면 버튼을 누른 입력이 다음 화면 버튼으로 이어지지 않는다.

## 7. 파일

- `Assets/Scripts/UI/TitleScreenView.cs`: 공용 전체 화면 부품(`FullScreenParts`)과 타이틀.
- `Assets/Scripts/UI/RequestSceneView.cs`: 요청 도입 장면.
- `Assets/Scripts/UI/AppShell.Entry.cs`: 시작 흐름·저장 상태 판정·새로 시작하기·도입 대상 판정.
- `AppShell.cs`: `Start`에서 `BeginEntry`, `Update` 맨 앞에서 `UpdateEntry`.
- `AppShell.Finale.cs`: 시작 화면 동안 P6 자동 개방 보류.
- `ProgressStore.ResetAll`(트랜잭션·성공 여부), `WorkStore.ResetAll`·`Save` 성공 여부.
- `WorkRequestData.introScene`·`introDetailFromLine`, `Request_A_T01`·`Request_B_ORD`.
- `UIKeys`의 `title.*`·`requestIntro.*`, `Strings_ko`·`Strings_en`.
