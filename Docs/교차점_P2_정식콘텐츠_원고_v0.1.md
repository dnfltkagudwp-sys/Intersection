## 0. 이 원고의 고정 규칙

### 0-1. P2 도달 상한

이 묶음을 전부 읽은 플레이어가 도달할 수 있는 최대치는 다음 두 가지다.

1. 서지훈이 여러 여성과 여러 익명 계정을 오래 조사했다. (불쾌함과 함께, 어떤 패턴을 찾고 있었다는 인상)
2. 강나린이 서지훈의 조사 자료와 윤서하 휴대전화의 지인 기록(B06) **양쪽에 등장한다**. 정유진에 이은 **두 번째 우연**.

윤서하가 계정을 운영했다, 같은 사람이 한 일이다, 강나린이 무엇을 당했다는 결론은 이 묶음의 어떤 기록에도 없다.

### 0-2. 화면 문구 금지어

플레이어가 읽는 원문(이미지 안 글자, 파일 미리보기, 검색 기록)에는 다음을 쓰지 않는다.

- 결론형: `피해자`, `가해자`, `동일범`, `범인`, `정답`, `증거`, `윤서하가 운영`, `유포`, `범죄`
- A07 전용 추가 금지(v0.3): `신고`, `동일 가해자`
- 내부 표기: `A`, `B`, `C`, `D`, `E` 역할 호칭, `A06-02` 같은 제작 참조, `D-128` 같은 상대 날짜, `P2`, 불변 ID, 자산 ID(`c-post-01` 등)

A06 캡처 안의 **플랫폼 UI 문구**(`신고 내역`, `운영 정책 위반` 등)는 실제 앱 화면이므로 허용한다. 서지훈이 직접 쓴 A07과 검색어에는 `신고`도 쓰지 않는다.

### 0-3. 날짜 표기 원칙 (`caseDate` 보호)

- **이미지 안에는 달력 날짜를 넣지 않는다.** 캡처 속 SNS 화면은 실제 앱처럼 `1일`, `6주` 같은 **상대 시간**만 쓰고, 상태바에는 시각만 있다. `caseDate`를 바꿔도 이미지를 다시 만들 필요가 없다.
- **A07처럼 서지훈이 직접 적은 날짜**는 `{date:-180}` 토큰으로 쓴다(확정, 구현 선행 필요).
  - 문법: `{date:N}`, N은 정수 상대 일수. `caseDate + N일`을 계산한다.
  - 출력: 짧은 월/일(예: `4/8`). 형식 문자열은 `Strings_ko`의 문자열 키로 둔다.
  - 화면 렌더링과 전역 검색은 같은 변환 결과를 쓴다(원본 토큰 문자열은 검색되지 않음).
  - 검증 오류: 알 수 없는 토큰 이름, `{date:abc}`처럼 숫자가 아닌 값, 범위 밖 값(제안: `-3650 ≤ N ≤ 0`, 고인이 사망 뒤에 쓴 날짜는 없으므로), 닫히지 않은 `{`.
  - 원본 문구와 변환 결과 모두 증거 ID·내부 ID·작가 메모 검사.
  - 지원 범위는 파일 표시 문구(`FileRecord.visibleText`)만. 사진 전사본은 이미지에 박힌 글자라 토큰을 쓰면 오류.
- 이 원고의 `D-180 14:34`는 내부 기록 시각(`time.dayOffset`/`hour`/`minute`)이다. **이 원고의 시각이 v0.3의 A06·D01·A07 시제품 시각을 대체한다.** v0.3에서 고정이었던 것은 날짜 값이 아니라 `B06-P1 D-134 → B06-M1/M2 D-132·D-131 → @smallroom_08 게시 D-128 → 서지훈 첫 캡처 D-127`의 선후관계다.

### 0-4. `visibleText` 전사 규칙

- 이미지가 있는 파일의 `visibleText`는 **이미지 안에서 읽을 수 있는 글자의 정확한 전사본**이다. 블록 종류는 모두 `Text`(A07만 `Table` 포함).
- 전사 대상은 콘텐츠 본문뿐이다: 계정명, 게시물 본문, 댓글, 프로필 소개, 게시물에 표시된 상대 시간, 앱 안내 문구, 이미지 자체에 박힌 읽을 수 있는 글자.
- 상태바 시각·배터리·통신 상태, 아이콘 숫자 배지는 전사하지 않는다(확정).
- 줄바꿈: 작성자가 의도한 문단 구분과 수동 줄바꿈(전사본의 줄)은 보존한다. 한 문단 안에서 화면 폭 때문에 생기는 자동 줄바꿈은 캡처 템플릿에 맡기며, 검색과 `visibleText` 대조에서는 자동 줄바꿈 차이를 무시한다. 글자 내용·문장 순서·문단 구분은 화면과 `visibleText`가 일치해야 한다(2026-10-13 규칙 수정). `@`는 화면에 보이는 경우에만 쓴다.
- 증거 ID·작가 메모·역할 키·자산 ID·후반 해설은 넣지 않는다. 각 기록의 `authorNote`에 쓰는 설명은 검색되지 않는다.

### 0-5. 공통 캡처 화면 규칙 (A06·D01)

| 항목 | 기준 |
| --- | --- |
| 캔버스 | 세로 1080×2340 PNG(휴대전화 전체 화면 캡처). 게임 휴대전화 상세 보기 비율과 최종 확인 필요 |

| 게시 시각 | SNS식 상대 시간(`1일`, `3일`, `6주`). 기록 시각에서 역산한 게시 시점은 각 기록에 내부값으로 적음 |

| 서지훈이 한 편집 | 없음. 서지훈은 캡처를 편집하지 않는다. 화면 밖으로 잘린 부분은 스크롤 위치 때문이다 |
| 압축 | 게시 이미지는 플랫폼 JPEG 재압축(품질 약 70, 8×8 블록 흔적이 확대 시 보이는 정도), 캡처 자체는 무손실 PNG. A06-02만 재캡처라 UI 위 이미지에 한 번 더 압축 흔적 |
| 제3자 계정 | 댓글 등에 나오는 일반 이용자 계정명은 실존 서비스·인물과 겹치지 않는 임의값. 사건 계정명·인물명과 글자 겹침 금지 |
| 성적 표현 | 없음. 사진은 평범한 착장·일상 사진과 얼굴 가림 스티커, 텍스트 조각만 사용 |

### 0-6. 런타임 ID

A06/D01/A07/D01-S 21건은 이미 에셋과 불변 ID가 발급돼 있다(시제품 자리 표시). **정식 콘텐츠로 교체할 때 ID는 그대로 유지**하고 시각·표시 문구·이미지만 바꾼다. 이번 원고는 새 기록을 추가하지 않는다. A10은 기록이 아니라 다른 기록 안의 문자열 묶음이라 ID가 없다.
